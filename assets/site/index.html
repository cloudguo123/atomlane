One decision loop

Parallelism is compiled,
not guessed.

AtomLane sits between a coding agent’s plan and local execution. It accelerates only the work whose dependencies, effects, outputs, and resource needs can be bounded.

01 / ASSESS

Find real work

Recognize tests, builds, containers, batch jobs, and long-running scripts worth evaluating.

02 / PROVE

Compile atomic lanes

Model dependencies and reject overlapping writes, unsafe state, and unclear execution boundaries.

03 / SIZE

Match the host

Allocate CPU, memory, workers, and accelerators across every active AtomLane session.

04 / RUN

Stay observable

Stream live state, contain failures, and report measured per-run and cumulative savings.

No four-worker ceiling

Every machine gets its own plan.

The scheduler does not encode a fixed “4×” target. Four lanes belong only to the controlled public benchmark.

64runtime worker ceiling

Actual concurrency is usually lower and is recalculated from current conditions.

CPU-boundStarts from physical cores; understands Apple performance/efficiency topology and SMT.
I/O-boundAllows bounded oversubscription when the host has safe capacity.
Shared hostCoordinates concurrent Codex tasks instead of letting each one assume it owns the computer.
