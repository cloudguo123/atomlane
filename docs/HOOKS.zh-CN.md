# AtomLane Hooks 与实时指示器

AtomLane 0.15.0 新增插件内置的 `UserPromptSubmit` Hook。安装后不再依赖用户
每次都记得主动点名：模型开始工作前，每个新提交的任务都会得到一次快速、可见的
加速预检。

## 实际运行的内容

Hook 接收 Codex 标准的 `UserPromptSubmit` JSON 事件，只检查其中的 `prompt`
字符串，并返回三类固定建议之一：

- **直接执行路径**：当前提示词里没有具体的本地执行批次。
- **到执行边界再检查**：可能需要本地执行，但提示词本身没有证明存在值得并行的批次。
- **可能适合并行，必须先做安全计划**：提示词提到了并行、重复项或长批次；真正执行
  前仍须检查并编译计划。

分类器不读取仓库、会话记录、环境或用户文件；自身不联网、不执行目标代码、不修改
任何内容，从不拦截提示词，也不会宣称并发已经安全。它不会把原提示词复制到输出中，
并明确保持用户提交的请求为首要指令。命令通过 Python 隔离且不加载 `site` 的模式
（`-I -S`）启动，忽略环境变量触发的启动定制。

到达真正的执行边界时，`$accelerate-local-work` 才检查实际工作；只有
`atomic_task_plan` 证明控制流、依赖、副作用、生命周期、执行域和资源均兼容，
`atomic_exec` 才能运行并行计划。短任务、单个任务、共享状态写入或副作用不确定的
工作继续直接或串行执行。

## 第一次信任

Codex 不会自动信任插件内置 Hook。安装或升级 AtomLane 后：

1. 新建一个 Codex 任务。
2. 打开 **Hooks**。
3. 检查 AtomLane 的 `UserPromptSubmit` 命令和来源路径。
4. 如果定义与安装版本一致，选择信任并启用。

Hook 定义变化会改变其哈希，因此未来升级后 Codex 可能再次要求检查。这是安全机制，
不是故障。即使 Hook 保持禁用，AtomLane 的显式 Skills 与 MCP 工具仍可使用。

## 实时执行

Hook 结果只是预检，不是执行指示器。当 AtomLane 真正接纳一个预计超过 10 秒的
任务时，MCP App 指示器和可轮询运行器会显示已用时间、运行/完成/失败数量、活跃原子、
峰值并发、当前预计节约时间，以及经过实测的本次和累计节约时间。节约数字只来自
实际执行计时。

## 升级后出现 `Unexpected response type`

旧任务可能保留类似 `ui://widget/atomlane-indicator-0.13.0.html` 的版本化 MCP
App 资源地址。在 0.15.0 之前，新服务端会拒绝旧地址，还会在资源协议位置返回工具
调用形状的错误，因而反复出现 `Unexpected response type`。

AtomLane 0.15.0 会兼容格式严格的历史指示器地址并原样返回请求 URI，同时只对外公告
当前版本资源；URI 参数缺失或类型错误会返回 JSON-RPC `Invalid params`，无关 URI
字符串会返回 `Resource not found`，两条路径都不会再伪装成工具结果。升级后请新建
任务，让 Codex 同时重新加载 Hook 和 MCP 元数据。
